---
title: Server SDKs
description: Integrate merchant payments, payouts, refunds, payment links and signed webhooks in your backend language.
---

Choose the client for your server. Each SDK uses the HTTPS API origin assigned to your merchant, your merchant ID, and a test or live API key. Obtain the package or source distribution from your OrsunPay integration contact.

| Language | Requirements | Start here |
| --- | --- | --- |
| JavaScript / TypeScript | Node.js 20+, ESM or CommonJS | [Node.js SDK](/sdks/node) |
| Go | Go 1.22+ | [Go SDK](/sdks/go) |
| PHP | 64-bit PHP 8.1+, PSR-18 transport and PSR-17 factories | [PHP SDK](/sdks/php) |
| Java / Kotlin | JVM 17+, Maven-compatible | [Java SDK](/sdks/java) |
| C# | .NET 8+ | [.NET SDK](/sdks/dotnet) |
| Python | Python 3.11+, synchronous or asyncio | [Python SDK](/sdks/python) |
| Ruby / Rails | Ruby 3.1+, Bundler for Rails | [Ruby SDK](/sdks/ruby) |
| Rust | Rust 1.90+, Tokio | [Rust SDK](/sdks/rust) |

All eight clients create sales and payouts, look up and list payments, manage payment links, request and track refunds, and verify webhook signatures. Store the order reference and a stable idempotency key before sending a write. A successful HTTP response can still describe a pending or declined payment. [First payment](/quickstart) · [Payment states](/payments)

For operations outside your SDK's method list, including usage billing, use the [HTTP reference](/api-overview). For a browser checkout, use the [checkout widget](/js-widget) or [cashier](/cashier). Keep the merchant key on the server.
